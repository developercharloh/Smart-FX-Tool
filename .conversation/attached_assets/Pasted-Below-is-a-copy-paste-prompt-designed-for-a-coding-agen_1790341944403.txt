Below is a copy-paste prompt designed for a coding agent. It builds the system as a Binance-connected reversal intelligence engine first, with execution controls separated so you can test it safely before enabling live trading.

Build a production-ready Binance Reversal Intelligence & Trading Model.

1. CORE OBJECTIVE

Build a model specifically connected to the Binance API that continuously monitors Binance-listed crypto assets and identifies potential:

- Strong Bullish Reversals
- Strong Bearish Reversals
- Developing Bullish Reversals
- Developing Bearish Reversals
- No-Trade conditions

The primary focus is detecting market reversals, particularly on volatile assets and meme coins, while minimizing false signals.

The system must support:

- Binance Spot market data
- Binance Futures market data
- Binance account information
- Spot trading
- Futures trading
- Binance Convert where supported by the official API
- Real-time WebSocket data
- Historical market data
- Backtesting
- Paper trading
- Risk management
- Signal alerts
- Optional automated execution

Do NOT claim that the model can predict the market with certainty. All signals must be presented as probability/confidence-style analytical signals, not guaranteed outcomes.

Create three modes:

Never expose Binance API secrets to the browser/frontend.

Bearish divergence

14. MULTI-TIMEFRAME CONFIRMATION

Do not generate a "Strong Reversal" merely because the smallest timeframe shows a reversal.

Example:

5m = bullish reversal
15m = bullish confirmation
1h = support/reversal structure

This should produce substantially stronger confirmation.

But:

5m = bullish reversal
15m = bearish
1h = strong bearish trend

should reduce the confidence score.

Create a multi-timeframe alignment score.

40. FINAL REQUIREMENT

Before writing code:

1. Inspect the existing project structure.
2. Identify the existing frontend/backend framework.
3. Identify the database.
4. Identify the deployment environment.
5. Identify existing authentication.
6. Identify existing Binance integrations.
7. Reuse existing architecture where appropriate.
8. Do not unnecessarily rewrite working components.
9. Check current official Binance API documentation for every endpoint being implemented.
10. Clearly separate analysis, paper trading, and live execution.

Then implement the system incrementally.

After each major phase:

- Run tests.
- Fix TypeScript/build errors.
- Verify API behavior.
- Verify WebSocket reconnection.
- Verify database writes.
- Verify signal calculations.
- Verify that no secret credentials reach the frontend.

The final product should function as a real-time Binance market-reversal intelligence platform with optional Spot/Futures execution, rather than simply being an RSI-based trading bot.
